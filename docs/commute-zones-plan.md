# 추천 생활권 기획 (역세권·버스권)

작성일 2026-10-05 · 상태: 1~3단계 구현됨 (디버그 화면 `/debug/areas`에서 확인)

출근지 기준 추천을 **법정동 대신 "역세권 생활권(도보 15분)"과 "버스권(행정동)" 단위로 묶고**, 통근시간은 생활권마다 **대표값 하나**로 보여준다. 계산은 지금의 H3 앵커(약 460m 격자)를 그대로 쓰고, 묶음 단위만 바꾼다.

## 1. 왜 바꾸나

지금 추천은 앵커를 만든 뒤 **법정동마다 하나만** 남긴다. 큰 법정동은 통근시간이 다른 동네가 한 점으로 뭉친다.

| 법정동 | 앵커 수 | 동 끝~끝 거리 |
| --- | --- | --- |
| 관악구 신림동 | 21 | 4.7km |
| 관악구 봉천동 | 15 | 4.3km |
| 연수구 송도동 | 9 | 6.4km |

(2026-10-05, 3개 구 + 일부 지오코딩 기준)

행정동으로 나눠도 1~2km라, 한 동이 두 역으로 갈리거나 역 앞과 언덕 위가 섞인다. **통근시간을 가르는 건 동 경계가 아니라 "어느 역까지 걸어가느냐"**다. 같은 역을 쓰는 곳끼리 묶어야 대표값 하나가 의미를 가진다.

## 2. 단위 정의

| 용어 | 정의 | 용도 |
| --- | --- | --- |
| 앵커 | 실거래 건물을 H3 해상도 8(한 변 약 460m)로 묶은 셀, 대표 좌표는 실제 거래 건물 | 계산 단위 |
| 역세권 생활권 | 한 역에서 **도보 15분** 안의 앵커 묶음 | 묶음·운영 단위 |
| 버스권 | 도보 15분 안에 역이 없는 앵커를 **행정동** 단위로 묶은 것 | 묶음·운영 단위 |

부동산 시장은 "신림역 도보 7분"처럼 역 기준으로 말하고, 중개사무소도 역 주변에 모여 있다. 생활권을 영업 단위로도 그대로 쓸 수 있다.

## 3. 생활권 만드는 규칙

1. **역 목록**: 수도권 지하철·경전철·광역철도 역 좌표와 노선 (8장).
2. **앵커 → 역 배정**: 앵커 대표 좌표에서 도보 15분 안의 역 중 **가장 가까운 역**에 배정한다.
   - 도보 15분 ≈ 직선 1km로 시작한다 (보행 경로 우회를 감안해 4km/h × 15분 = 1km). 실험 후 조정.
   - 여러 역에 걸치면 가장 가까운 역이 주 역, 나머지는 보조 역으로 기록한다.
3. **버스권**: 도보 15분 안에 역이 없으면 그 앵커의 **행정동**으로 묶는다.
4. **이름**: `<행정동> · <역>권` (예: "서원동 · 신림역권"), 버스권은 `<행정동> · 버스권`. 생활권에 행정동이 여럿이면 앵커 점수 합이 가장 큰 행정동 이름을 쓴다.
5. **대표 좌표**: 생활권 안 앵커 중 거래 수 가중 medoid. 항상 실제 거래 건물 좌표다.
6. **생활권 통계**: 앵커들의 거래 수·유형별 개수·월세/전세 중위값을 합산해 생활권에 저장한다.

역이 촘촘한 도심은 생활권이 작게, 외곽은 크게 나뉜다. 실제 통근 차이와 같은 방향이다.

## 4. 통근시간 계산 (대표값)

**대표값 = 생활권 대표 좌표에서 출근지까지의 대중교통 최단 시간** (평일 08:00 출발, 환승 없는 최단도 함께 저장).

계산은 출근지가 반복된다는 점을 이용해 두 갈래로 나눈다.

```
역세권 생활권:  대표 좌표 ──도보(자체 계산)──▶ 주 역 ──TMAP──▶ 출근지
버스권:         대표 좌표 ─────────────TMAP─────────────▶ 출근지
직주근접:       대표 좌표 ──────도보(자체 계산, 15분 이내)──────▶ 출근지
```

- **역세권**: `대표값 = 도보(대표 좌표→역) + TMAP(역→출근지)`. 역→출근지 결과는 출근지 근처 요청끼리 재사용된다.
- **버스권**: 대표 좌표에서 출근지까지 TMAP을 직접 호출한다.
- **직주근접**: 대표 좌표에서 출근지까지 직선 도보(4km/h, 역세권과 같은 기준)가 **15분(직선 1km) 이내**면 생활권 종류와 상관없이 TMAP을 부르지 않고 `대표값 = 도보 시간`으로 넣는다 (`walkOnly`). 아주 가까우면 대중교통 경로가 없거나 도보보다 길게 나와 바로 옆 동네가 빠지기 때문이다. 허용 시간 최솟값이 20분이라 항상 "시간 내"로 들어가고, 유형·예산 조건은 그대로 적용한다. 함께 고려할 곳도 장소마다 따로 판단한다.
- **캐시 키**: `제공자 | 출발(역 ID 또는 생활권 ID) | 도착 좌표(소수 셋째 자리, 약 100m) | 시간대(weekday-0800) | 생활권 데이터 기준일`. 30일 유지.
- **분류**: 시간 내 / 환승 없이 여유 시간 내 / 초과 (지금 규칙 그대로).

## 5. TMAP 비용과 호출 전략

SK open API 요금 (2026-10 확인):

| API | Free | Premium |
| --- | --- | --- |
| 대중교통 | 10건/일 | 0.88원/건 |
| **대중교통 요약정보 (사용 중)** | **10건/일** | **0.55원/건** |

- 무료 10건/일로는 요청 하나도 처리할 수 없다. **Premium 계약이 전제**다 (사용량 후불, 초과 시 차단 해제는 별도 계약).
- 요청 1건 = 후보 생활권 최대 약 40곳 실측 → **약 22원**. 캐시가 쌓이면 더 줄어든다.
- 업무지구 사전 계산 = 수도권 역 약 600곳 × 업무지구 30곳 ≈ 18,000건 → **약 1만 원**, 분기마다 갱신.

**호출 전략 (단계)**
1. **처음**: 요청마다 실측 + 캐시 (사전 계산 없음). 들어온 출근지를 기록한다.
2. **요청 전 거르기**: 반경 안 모든 생활권을 직선거리 추정으로 먼저 거르고(호출 없음), 남은 곳 중 점수 상위 약 40곳만 TMAP 실측, 나머지는 "추정" 표시.
3. **반복되는 업무지구가 보이면**: 그 업무지구만 "역 → 업무지구"를 미리 계산한다. 비용이 작아 기준은 "같은 업무지구 요청이 주 N건 이상"처럼 단순하게 둔다.

## 6. 누가 어떻게 쓰나

| 대상 | 보는 것 | 쓰는 방식 |
| --- | --- | --- |
| 운영자 | 요청별 추천 생활권 목록 (통근 대표값, 시세, 유형 분포) | 상위 생활권의 역 주변 중개사에게 연락 |
| 중개사 | 제안 링크에 생활권 이름과 범위 | 자기 영업권 안 매물만 제안 |
| 사용자 | **생활권은 보지 않는다** | 매물이 제안되면 매물 단위로만 "신림역 도보 6분 · 강남 21분" |

사용자에게 동네를 먼저 보여주지 않는 원칙은 유지한다. 생활권은 운영·중개사용이다. 지금의 `/debug/areas`는 개발 확인용이다.

## 7. 검증 실험 (단위 확정 전)

역세권으로 갈지 확신이 없으므로, **묶음 안 통근시간이 얼마나 비슷한가**로 판단한다.

1. 출근지 3곳: 강남역, 여의도(IFC), 판교역.
2. 같은 앵커들을 두 방식(행정동 / 역세권 15분)으로 묶는다.
3. 묶음마다 앵커 3~5개를 TMAP으로 실측한다.
4. 묶음 안 통근시간 편차(최대−최소, 중앙값)를 비교한다.
5. **판단 기준**: 대표값을 쓰므로 묶음 안 편차가 **±5분 이내**인 비율이 높은 쪽을 택한다. 둘 다 낮으면 역세권 반경을 10분으로 줄여 다시 본다.

규모: 약 60묶음 × 4앵커 × 3출근지 ≈ 700건 → Premium 기준 약 400원. 무료 한도로는 불가.

## 9. 구현 순서

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1. 데이터 ✅ | `stations`(브이월드 장소 검색 + 네이버 보충, 671개), `anchor_admin_areas`(네이버 역지오코딩) | 수도권 앵커 전부에 배정 |
| 2. 생활권 생성 ✅ | `commute_zones`, `anchor_zone_assignments`, `pipeline:zones` | 다시 실행해도 같은 결과 |
| 3. 계산 전환 ✅ | 생활권 단위, 역 경유 계산(도보 + 역→출근지), 유형·예산 조건, 직선 추정 거르기, 상위 40곳 실측 | 디버그 화면에서 조건에 맞는 생활권만 확인 |
| 4. 검증 실험 | 7장 실험 스크립트와 결과표 | 단위 확정 (역세권 15분 유지/조정) |
| 5. 운영 화면 | 요청별 추천 생활권을 운영자 화면에 | 운영자가 생활권 보고 중개사 연락 |
| 6. 사전 계산 | 반복 업무지구 "역 → 업무지구" 배치 | 해당 출근지 요청 시 TMAP 호출 0건 |

1~3 단계는 Premium 계약 전에도 진행할 수 있고, 4단계부터 TMAP 호출이 필요하다.

## 구현 메모 (1~3단계)

- 역 출처: 공공데이터 표준 역사 API는 폐기됨, OpenStreetMap Overpass는 응답 불안정 → 브이월드 장소 검색(지하철역·일반철도역·기타철도역 분류) + 브이월드에 없는 역(동탄역)은 네이버 지역 검색으로 보충 (`SUPPLEMENT_STATIONS`).
- 생활권 시세는 유형별로 따로 낸다: 원룸 = 연립다세대 전용 33㎡ 이하, 투룸 = 33~60㎡, 오피스텔, 아파트. 단독다가구는 위치가 없어 빠진다.
- 조건 일치 = 고른 유형 중 거래 3건 이상이고 시세 중위값이 예산 안(조정 가능 +10%, 상담 +20%)인 유형이 하나라도 있음.
- 월세 예산은 전월세 전환을 적용한다: 보증금 1,000만원당 월세 5만원 (`RENT_PER_DEPOSIT`). 상한 3,000/50이면 보증금 1,000짜리는 월세 60까지. 보증금이 상한을 넘으면 맞지 않음.
- 실측 상한 40곳(`AREA_SETTINGS.measureLimit`), 나머지는 직선 추정으로 표시. 결과에는 조건과 통근을 모두 만족한 생활권만 담는다.
- 직주근접 기준은 `AREA_SETTINGS.walkCommuteMaxMinutes`(15분), 계산은 `walkCommuteOf`. 모든 장소에 걸어서 갈 수 있는 생활권은 실측하지 않으므로 실측 상한에 세지 않는다. 운영·디버그 화면과 예시 매물에는 "걸어서 n분"으로 보인다.
- 2026-10-05 기준: 앵커 2,267 → 생활권 889 (역세권 536, 버스권 353). 지오코딩이 끝나면 `pipeline:anchors` → `pipeline:zones`를 다시 돌린다.

## 10. 결정 사항

**결정됨**
- 통근 표시: 생활권마다 **대표값 하나**
- 역세권 기준: **도보 15분** (직선 약 1km로 시작)
- 역에서 먼 곳: **행정동 단위 버스권**
- 직주근접: 출근지까지 **걸어서 15분 이내**인 생활권은 대중교통 계산 없이 항상 포함 (2026-10-06)
- 사용자에게는 생활권 비노출, 운영·중개사용

**미결정**
- [ ] 묶음 단위 최종 확정: 역세권 vs 행정동 → 7장 실험 후
- [ ] TMAP Premium 계약 여부와 시점
- [ ] 업무지구 사전 계산 시작 기준 (요청 몇 건부터)
- [ ] 역 데이터 출처 확정 (최신 노선 반영 여부)
